## 📊 V1.2 Logic Comparison

### Before V1.2 (OLD - Discarded)
```javascript
// Income Transaction
Income: 100,000 EGP
→ Project Safe: 80,000 EGP
→ Office Revenue: 20,000 EGP (20% immediate)

// Expense Transaction
Expense: 10,000 EGP
→ Project Safe: 70,000 EGP (deducted from 80k)
→ Office Revenue: 20,000 EGP (no change)
```

### After V1.2 (NEW - Implemented)
```javascript
// Income Transaction
Income: 100,000 EGP
→ Project Safe: 100,000 EGP (full amount)
→ Office Revenue: 0 EGP (no profit yet)

// Expense Transaction (Direct)
Expense: 10,000 EGP
→ Project Safe: 88,000 EGP (100k - 10k - 2k profit)
→ Office Revenue: 2,000 EGP (20% of expense)

// Expense Transaction (Inventory)
Inventory Purchase: 15,000 EGP
→ Project Safe: 73,000 EGP (88k - 15k)
→ Office Revenue: 2,000 EGP (no change, profit deferred)

// Inventory Usage
Usage: 5,000 EGP
→ Project Safe: 72,000 EGP (73k - 1k profit)
→ Office Revenue: 3,000 EGP (2k + 1k profit)
```

## 🎓 Key Concepts

### Project Safe Balance
- **What:** The actual cash holding of the project
- **When Updated:** On every income and expense
- **Alert:** RED when negative
- **Purpose:** Real-time cash flow tracking

### Profit on Expense
- **What:** Profit is recognized when money is spent, not received
- **Why:** More accurate profit tracking
- **How:** `Profit = Expense × (ManagementFeePercent / 100)`
- **Transfer:** From Project Safe to Office Revenue

### Work Orders (Cost Items)
- **What:** Specific agreed work items (e.g., "Ceramic 100m²")
- **Purpose:** Granular project tracking
- **Tracking:** `totalPaid` vs `estimatedTotal`
- **Status:** OPEN, COMPLETED

### Arabic Categories
- **What:** Client-provided Arabic terms for transaction categories
- **Groups:** Materials (خامات), Labor (مصنعية), Services (أخرى)
- **Total:** 29 categories
- **Usage:** Primary labels in UI dropdowns
