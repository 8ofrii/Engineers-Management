# V1.2 Migration Quick Guide

## ⚠️ IMPORTANT: Database Migration Decision

You have **3 options** to handle the database migration:

---

## Option 1: Manual SQL Migration (SAFEST - Recommended for Production)

**Pros:** No data loss, full control  
**Cons:** Requires manual execution

### Steps:

1. **Type N** in the current Prisma prompt to cancel the reset
2. Connect to your PostgreSQL database
3. Run the SQL file: `server/prisma/migrations/manual_v1_2_migration.sql`

```bash
# Using psql
psql -h dpg-crp9o3lds78s73d6ktpg-a.frankfurt-postgres.render.com \
     -U your_user \
     -d dood \
     -f server/prisma/migrations/manual_v1_2_migration.sql

# Or copy-paste the SQL into your database GUI (pgAdmin, DBeaver, etc.)
```

4. After running the SQL, mark it as applied:
```bash
npx prisma migrate resolve --applied manual_v1_2_migration
```

---

## Option 2: Prisma Migrate with Baseline (Good for Development)

**Pros:** Automated, Prisma handles it  
**Cons:** Requires careful baseline setup

### Steps:

1. **Type N** in the current prompt
2. Create a baseline of current state:
```bash
npx prisma migrate resolve --applied "0_init"
```

3. Then create the new migration:
```bash
npx prisma migrate dev --name v1_2_profit_on_expense
```

---

## Option 3: Reset Database (ONLY for Development/Testing)

**⚠️ WARNING:** This will **DELETE ALL DATA**

**Pros:** Clean slate  
**Cons:** Loses all existing data

### Steps:

1. **Type Y** in the current prompt
2. Prisma will reset and apply all migrations
3. You'll need to re-seed your database

**Only use this if:**
- You're in a development environment
- You have a backup of your data
- You're okay with losing all current data

---

## 🎯 Recommended Approach

For your production database on Render:

1. **Type N** now
2. Use **Option 1 (Manual SQL Migration)**
3. This ensures no data loss

---

## After Migration

Once the database is migrated, restart your server:

```bash
cd server
npm run dev
```

Then test the new endpoints:

```bash
# Test health check
curl http://localhost:5000/api/health

# Test new endpoint (requires auth)
curl http://localhost:5000/api/project-cost-items
```

---

## Verification

After migration, verify the changes:

```bash
npx prisma studio
```

Check for:
- ✅ `project_cost_items` table exists
- ✅ `projects.projectSafeBalance` column exists
- ✅ `transactions.projectCostItemId` column exists

---

## Rollback (If Needed)

If something goes wrong with the manual migration:

```sql
-- Rollback script
ALTER TABLE "transactions" DROP CONSTRAINT IF EXISTS "transactions_projectCostItemId_fkey";
ALTER TABLE "transactions" DROP COLUMN IF EXISTS "projectCostItemId";
ALTER TABLE "projects" DROP COLUMN IF EXISTS "projectSafeBalance";
DROP TABLE IF EXISTS "project_cost_items";
```
