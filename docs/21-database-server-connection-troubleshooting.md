# Database and server connection troubleshooting

## ملخص المشكلة

الخطأ الذي ظهر عند فتح Campus ليس سببه السطر `src/lib/db.ts:59` نفسه.
هذا السطر هو أول مكان نفّذ فيه التطبيق `getPool().connect()`، ولذلك ظهر في
الـstack trace، لكنه لا يحدد سبب فشل الاتصال.

بدأت المحاولة من `FeatureRouteGuard` لأن Layout الخاص بـCampus يقرأ feature
flags عند فتح الصفحة. هذه القراءة تستدعي تهيئة قاعدة البيانات، فظهر الخطأ أثناء
تحميل الصفحة قبل الوصول إلى تسجيل الدخول.

يوجد خطآن منفصلان تم رصدهما:

| الخطأ | معناه | الإجراء المطلوب |
| --- | --- | --- |
| `connect EACCES 148.251.171.147:5432` | بيئة التشغيل المعزولة منعت اتصال TCP الخارجي قبل أن يصل PostgreSQL إلى مرحلة التحقق من الحساب | شغّل المشروع من Terminal عادي خارج البيئة المعزولة |
| PostgreSQL `28P01` | الاتصال وصل فعلاً إلى PostgreSQL، لكن اسم المستخدم أو كلمة المرور مرفوضان | صحّح بيانات الدخول في ملف `.env` الفعلي ثم أعد تشغيل Next.js بالكامل |

بالتالي إزالة `EACCES` وحدها لا تعني أن تسجيل الدخول سيعمل. يجب أيضاً حل
`28P01` ببيانات PostgreSQL صحيحة.

## إعداد قاعدة البيانات المستخدم فعلياً

الكود في `src/lib/db.ts` يدعم طريقتين للإعداد، بترتيب الأولوية التالي:

1. `DATABASE_URL`
2. متغيرات `PG*` أو `DB_*`

إذا كان `DATABASE_URL` موجوداً، فسيتجاهل التطبيق `PGPASSWORD` و`DB_PASSWORD`
وباقي متغيرات الاتصال المنفصلة. لذلك لا تترك `DATABASE_URL` قديماً ثم تعدّل
`DB_PASSWORD` وتتوقع أن يستخدمه التطبيق.

استخدم طريقة واحدة فقط من الطريقتين الآتيتين داخل ملف `.env` الموجود في جذر
المشروع.

### الاختيار الأول: DATABASE_URL

```dotenv
DATABASE_URL=postgresql://postgres:<URL_ENCODED_PASSWORD>@148.251.171.147:5432/<DATABASE_NAME>
DB_SSL=true
```

لو كانت كلمة المرور تحتوي رموزاً مثل `@` أو `:` أو `/` أو `#`، يجب تحويلها إلى
URL encoding قبل وضعها داخل `DATABASE_URL`.

### الاختيار الثاني: متغيرات منفصلة

```dotenv
PGHOST=148.251.171.147
PGPORT=5432
PGUSER=postgres
PGPASSWORD=<CORRECT_PASSWORD>
PGDATABASE=<DATABASE_NAME>
PGSSLMODE=require
```

يمكن استخدام البدائل `DB_HOST`, `DB_PORT`, `DB_USERNAME` أو `DB_USER`,
`DB_PASSWORD`, و`DB_NAME`. لا تكرر الطريقتين معاً حتى لا يحدث التباس.

إذا كان PostgreSQL لا يستخدم SSL، احذف `PGSSLMODE=require` واجعل
`DB_SSL=false`. يجب مطابقة هذا الإعداد مع إعداد السيرفر الحقيقي.

> لا تضع كلمة المرور الحقيقية في هذا المستند، ولا ترسلها في screenshots أو
> logs. ملف `.env` مستبعد بالفعل من Git عن طريق `.gitignore`.

## خطوات الحل على جهاز التطوير

### 1. تأكد أن المنفذ يمكن الوصول إليه

من PowerShell عادي على نفس الجهاز:

```powershell
Test-NetConnection -ComputerName 148.251.171.147 -Port 5432
```

النتيجة المطلوبة:

```text
TcpTestSucceeded : True
```

- إذا كانت `False`: راجع firewall، عنوان السيرفر، فتح المنفذ `5432`، وإعداد
  `listen_addresses` في PostgreSQL.
- إذا كانت `True` ثم ظهر `28P01`: الشبكة سليمة والمشكلة في credentials فقط.

### 2. اختبر بيانات PostgreSQL مباشرة

إذا كان `psql` مثبتاً، استخدم `-W` حتى يطلب كلمة المرور بدون كتابتها داخل
الأمر أو حفظها في history:

```powershell
psql -h 148.251.171.147 -p 5432 -U postgres -d <DATABASE_NAME> -W
```

- نجاح فتح prompt الخاص بـPostgreSQL يثبت أن host، port، database، user،
  password، وSSL متوافقون.
- ظهور `28P01` هنا أيضاً يثبت أن كلمة المرور أو اسم المستخدم غير صحيحين على
  السيرفر، وليس أن المشكلة من Next.js.

### 3. احفظ القيم الصحيحة في `.env`

الملف المطلوب هو:

```text
<project-root>/.env
```

راجع خصوصاً:

- عدم وجود مسافات أو quotes زائدة حول كلمة المرور.
- اسم قاعدة البيانات صحيح وموجود.
- عدم وجود `DATABASE_URL` قديم يتغلب على القيم المنفصلة.
- إعداد SSL مطابق للسيرفر.

### 4. أوقف Next.js وأعد تشغيله بالكامل

Next.js يقرأ `.env` عند بدء العملية. الـrefresh في المتصفح لا يكفي بعد تغيير
بيانات الاتصال.

داخل Terminal عادي في جذر المشروع:

```powershell
npm.cmd run dev
```

يجب أن يظهر في البداية أن Next.js حمّل:

```text
Environments: .env
```

ثم افتح:

```text
http://localhost:3000/campus/explore
```

## لو استمر 28P01

يجب تنفيذ الخطوات التالية على سيرفر PostgreSQL نفسه بواسطة مسؤول قاعدة
البيانات:

1. التأكد أن المستخدم المكتوب في `.env` موجود ويمكنه تسجيل الدخول.
2. إعادة ضبط كلمة مرور المستخدم ثم نسخ القيمة الجديدة بدقة إلى `.env`.
3. التأكد من أن `pg_hba.conf` يسمح بعنوان IP الخاص بجهاز التطبيق ونوع
   authentication المستخدم.
4. التأكد من أن المستخدم لديه اتصال بقاعدة البيانات وصلاحيات schema اللازمة.

التطبيق يشغّل schema migrations من `initDb()` عند الإقلاع، ولذلك مستخدم قاعدة
البيانات يحتاج صلاحيات إنشاء وتعديل الجداول المطلوبة، أو يجب تشغيل migrations
بشكل منفصل بواسطة مستخدم مخصص له الصلاحيات المناسبة.

يفضل في بيئة production إنشاء مستخدم تطبيق مخصص بدلاً من استخدام مستخدم
`postgres` العام، مع منحه أقل صلاحيات لازمة للتطبيق والـmigrations.

## دليل سريع حسب كود الخطأ

- `EACCES`: سياسة أو sandbox محلي يمنع الاتصال الخارجي.
- `28P01`: PostgreSQL رفض password authentication.
- `ECONNREFUSED`: العنوان متاح لكن لا توجد خدمة تستمع على المنفذ، أو firewall
  يرفض الاتصال صراحة.
- `ETIMEDOUT`: مشكلة route أو firewall أو IP/port غير صحيح.
- `3D000`: اسم قاعدة البيانات غير موجود.
- `42501`: الحساب اتصل لكنه لا يملك الصلاحيات المطلوبة.

## النتيجة المطلوبة بعد الإصلاح

بعد نجاح الإعداد وإعادة تشغيل السيرفر:

1. لا يظهر `EACCES` أو `28P01` في Terminal.
2. تفتح صفحات Campus بدون database overlay.
3. تعمل عمليات Sign Up وSign In وقراءة session.
4. يتم حفظ `role=member` و`member_plan` للحسابات الجديدة في PostgreSQL.
5. يعمل refresh وتسجيل الخروج ثم الدخول مرة أخرى بدون فقدان الخطة المحفوظة.
